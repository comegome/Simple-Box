# Simple-Box

专为追求系统整洁、网络安全与纯净架构的个人 VPS 用户设计。避免防火墙滥开、内置未知二进制、明文 HTTP 暴露与多核心混合部署等隐患，全代码标准 Bash，透明可审计。

---

### 🖥️ 运行环境

* 系统：Ubuntu 24.04+ 或 Debian 12+（官方仓库内置 Caddy，无需任何第三方源）
* 硬件：x86_64 或 aarch64 处理器 + 256MB 及以上内存
* 网络：IPv4 公网地址（双栈 VPS 仅在 IPv4 上提供服务；不支持纯 IPv6 VPS）
* 客户端：Mihomo (Clash.Meta) 内核 $\ge$ v1.19.32，以完整支持 TUN 模式的 mips 用户态协议栈

---

### 🚀 一键安装

以 root 权限运行以下命令：

```bash
curl -fsSL https://raw.githubusercontent.com/comegome/Simple-Box/main/simple-box.sh -o /tmp/simple-box.sh && sudo bash /tmp/simple-box.sh
```

### ⌨️ 快捷指令

安装成功后，随时在终端任意目录下输入 `simbo` 即可打开控制台：

```bash
simbo
```

### 🛠️ 核心特性

* 支持 VLESS-Reality / Hysteria2 双协议节点
* 协议集合在**安装期**一次定死（两个都装 / 只 Reality / 只 Hy2），运行期没有开关位；要改集合重跑安装即可，凭证默认沿用
* **多出口（链式落地）**：入口机保留直连节点，可同时挂最多 4 个 Hysteria2 落地，每个落地一组独立入口端口
* 安装时自动探测本机已有站点，默认用它做伪装域名，并复用其证书（无需再申请）
* 使用 sing-box 单内核驱动，支持内核在线升级
* 纯 IPv4 架构：不读也不改系统的 IPv6 配置，双栈 VPS 上安装同样干净
* 安装时写入统一的网络基线（fq + BBR + TCP 缓冲/慢启动等 9 项），只覆盖服务商 sysctl 的同名键、不改写对方文件；卸载只删自己的文件
* 支持 IP 自签或 Cloudflare 托管域名（证书通过 acme.sh + DNS-01 自动申请与续期）
* 提供高度隐私保护的 Clash / Mihomo 托管配置及纯节点列表
* 支持自定义所有节点的统一名称前缀、中转节点后缀
* 所有端口（直连入口、链式入口、订阅端口）均可在菜单中修改
* 支持修改重置订阅地址的链接（旧链接立即作废）

#### 步骤 1：在 Cloudflare 添加 A 记录
1. 登录 [Cloudflare 控制台](https://dash.cloudflare.com/)，进入你的域名；
2. 左侧菜单 DNS → 记录 (Records) → 添加记录 (Add record)；
3. 填写：
   * 类型 (Type)：`A`
   * 名称 (Name)：二级前缀（例如 `node`、`o2`，根域用 `@`）
   * IPv4 地址：这台 VPS 的公网 IPv4
   * 代理状态 (Proxy status)：必须为“仅限 DNS”（灰色云朵）。开启小黄云 CDN 会阻断 UDP，Hysteria2 将完全无法连接。
4. 点击保存 (Save)。

#### 步骤 2：生成专属 API Token
1. Cloudflare 右上角头像 → 配置文件 (Profile)；
2. 左侧 API 令牌 (API Tokens) → 创建令牌 (Create Token)；
3. 找到模板“编辑区域 DNS (Edit zone DNS)”，点击“使用模板 (Use template)”；
4. 配置：
   * 令牌名称：任意（如 `simple-box-cert`）
   * 区域资源 (Zone Resources)：包括 (Include) → 特定区域 (Specific zone) → 选中目标域名
   * 其余保持默认
5. 底部点击“继续以显示摘要” → 创建令牌；
6. 复制生成的 Token（仅展示一次，妥善保存）。

#### 步骤 3：在 VPS 终端填入
安装时输入 Hysteria2 域名后，按提示粘贴 Token。脚本走 **DNS-01** 验证（不占用 80 端口），自动签发 ECC 证书并注册续期钩子——续期后自动同步到 sing-box 并重启服务。

#### 协议集合：安装期决定，运行期没有开关

安装向导第一问就是「装哪些协议」：

```
 1. Reality + Hysteria2
 2. 只装 Reality
 3. 只装 Hysteria2
```

* 选择结果写进 `env.conf` 的 `PROTO_SET`，`config.json`、订阅、面板状态全部由它派生
* 运行期没有任何入口能改集合（没有停用/启用菜单，也没有 `VL_ENABLE` 之类的开关位）——要增删协议就重跑安装，凭证默认沿用，客户端订阅不用改

#### 菜单 7：伪装站点

为 Reality 生成一个「自己域名 + 本机真站点 + 真证书」的回落，替代借用 `www.icloud.com` 这类外部 SNI。站点由 `camo/camo-site.py` 生成：纯静态、无 JS、无外部字体、无图片、CSS 内联、全站 `noindex`，页面之间只用相对链接。

```
 1. 生成 / 重建站点      （选域名 → 选内容源 → 选版式）
 2. 删除站点
 0. 返回主菜单
```

* **内容源**：ESO（天文）/ Wikimedia（开放知识）/ W3C（Web 标准）/ BHL（自然史）。一个站只用一个源，题材与来源一致；站名、版式、文章子集由「域名」派生，不同机器不会撞成同一份。
* **证书**：优先复用本机已有证书（`/etc/sing-box/cert` 或 `/etc/ssl/<域名>`）；没有就询问 Cloudflare Token 走 DNS-01 现签一张，写 `/etc/ssl/<域名>`，**不会覆盖 Hy2 的证书**。
* **证书实例分家**：内容域证书用独立 acme 实例 `/root/.acme.sh-site`（token 取 `/root/.cf-token-site`），接入域仍用 `/root/.acme.sh`。acme.sh 的 `SAVED_CF_Token` 是每个实例一份，两 zone 挤在一个实例里会让其中一个续期静默失败——这是 `example.com` 与节点域名分属两个 Cloudflare zone 时的必做项。
* **挂载**：Caddy 站点只监听 `127.0.0.1:9443`，公网 443 仍归 sing-box；Reality 在跑时自动翻转。
* **伪装域名可以填自己的**：安装时若填的域名 A 记录已指向本机、但本机还没有它的站点，安装会自动生成站点（证书走 DNS-01，可复用同 zone 的 Token），并把 Reality 的回落目标指向 `127.0.0.1:9443`。伪装域名与 Hy2 域名可以不同；不同 zone 时需为该域名单独提供 Token（`/root/.cf-token-site` 或现场输入）。
* **装完也能换伪装域名**：菜单「伪装站点」给新域名建站时会提示并自动切换 `VL_SNI`（客户端须重拉订阅）。Reality 在跑时，只有当前伪装域名能通过回落对外服务，所以这是一次性切换而不是并存。

验收：`curl -sk --resolve <域名>:9443:127.0.0.1 https://<域名>:9443/` 返回 200；`ss -ltnp | grep 9443` 只监听 127.0.0.1。

<summary>🔗 多出口（链式落地）完整配置步骤（点击展开）</summary>

### 它解决什么问题

单机节点只有「入口即出口」一种形态。当你在两地各有一台机器时，常见需求是：

* 入口机线路好（延迟低、抗封锁），但落地 IP 不理想；
* 落地机 IP 干净（流媒体、注册、解锁），但本地直连它丢包严重。

出站中转让 **终端连入口机（加密伪装），入口机再把流量交给落地机出口**。原有直连节点保持不变，入口机可以同时挂多个落地，每个落地一组独立的链式入口端口与订阅节点，客户端自己选走哪一条。

### 拓扑

```
客户端 ──Reality/Hysteria2(443/8443)──────────► 入口机 ──► 直出（默认，不改动）
       ├─Reality/Hysteria2(2053/2054)─exit-out──► 落地 A ──► 目标站
       └─Reality/Hysteria2(2083/2084)─exit2-out─► 落地 B ──► 目标站
```

* 直连节点：`FN-VLESS-Reality`、`FN-Hysteria2`
* 出口 A：`FN-VLESS-Reality-ISIF`、`FN-Hysteria2-ISIF`
* 出口 B：`FN-VLESS-Reality-SL`、`FN-Hysteria2-SL`
* 后缀只是标签，可在菜单里改成 `JP`、`US`、`SG2` 等
* 面板里的出站行按出口逐行显示**解析后的落地 IP**（每次刷新实时解析，不缓存），连接本身仍用域名——落地机换 IP 时只要改 DNS 就自动跟随

### 约束（先看这一条）

**落地机的 Hysteria2 必须能从入口机连通（UDP）。** 出口只支持 Hysteria2；落地侧 UDP 不通（安全组没放、被机房拦、或落地机只开了 TCP）时，这个落地就不能当出口——入口机的自检会报 `✗ 出站连不通`。

### 步骤一：准备落地机

在落地机上正常安装 Simple-Box，**启用 Hysteria2**：

1. 落地机的云厂商安全组 / 防火墙放行 `8443/udp`；
2. 记下落地机的订阅地址，形如：

   ```
   https://landing.example.com:8444/<24位token>/provider.yaml
   ```

   `provider.yaml` 里是该机全部节点参数。**不需要手抄密钥**，入口机会自己解析。

> 落地机自己不需要任何额外配置，也不用安装什么中转组件——它只是个普通节点。

### 步骤二：在入口机上新增出口

在入口机执行 `simbo` → `3. 出站管理` → `2. 新增出口`：

```
设置方式 [1=粘贴订阅地址导入 2=手动填写，默认 2]: 1
粘贴落地机的 provider.yaml 地址: https://landing.example.com:8444/<token>/provider.yaml
✓ 已导入落点 landing.example.com:8443
节点后缀 [EXIT2]: SL
链式入口端口 · Reality [2083]:
链式入口端口 · Hysteria2 [2084]:
✓ 出口 2 已保存（Hysteria2 → landing.example.com:8443，入口 2083/2084）
✓ 出站连通性正常
```

* 粘贴地址后自动识别地址、端口、密码、SNI（只认 Hysteria2 节点；找不到会直接报错）；
* 方括号里是当前值，**回车即沿用**；入口端口默认按上表的 CF 端口对给；
* 端口会校验：不能与 `443 / 8443 / 8444`、另一个出口的入口端口冲突，且上机前用 `ss` 确认空闲；
* 最后一行是自动连通性自检：`✓ 正常` / `✗ 连不通（端口没放行或密码不对）` / `⚠ IP 与落地机不一致（对方也在中转）`。

保存后脚本会立刻重建 `config.json`、刷新订阅并重启 sing-box，无需手工重启。

### 步骤三：验证四条链路

```
# 入口机上起临时客户端，比出口 IP 的 hash
via2053 / via2054 = 落地 A 的出口 IP
via2083 / via2084 = 落地 B 的出口 IP
```

1. `3. 出站管理` → `1. 查看出站详情`，核对每个出口的落点、入口端口与后缀；
2. `1. 原始订阅信息`，两个出口时应看到 **6 条**（2 直连 + 2×2 出口）；
3. 客户端重新拉订阅，逐个节点测出口 IP：`-ISIF` 两条应等于落地 A，`-SL` 两条应等于落地 B；
4. 直连节点测出来应等于**入口机**的 IP。

### 步骤四：编辑 / 删除出口

* `3. 编辑出口`：选编号后改落点、密码、后缀、两个入口端口（不换协议）；
* `4. 删除出口`：选编号并确认，该槽的 inbound、outbound、route 规则与订阅节点一并移除，订阅与 `config.json` 回到删除前的单出口形态。

### 生成的配置长什么样

```json
"inbounds": [
  { "tag": "vless-reality-in",  "listen_port": 443  },
  { "tag": "hy2-in",            "listen_port": 8443 },
  { "tag": "exit-vless-in",     "listen_port": 2053 },
  { "tag": "exit-hy2-in",       "listen_port": 2054 },
  { "tag": "exit2-vless-in",    "listen_port": 2083 },
  { "tag": "exit2-hy2-in",      "listen_port": 2084 }
],
"outbounds": [
  { "tag": "direct",    "type": "direct" },
  { "tag": "exit-out",  "type": "hysteria2", "server": "isif.example.com", "server_port": 8443 },
  { "tag": "exit2-out", "type": "hysteria2", "server": "sl.example.com",   "server_port": 8443 }
],
"route": {
  "rules": [
    { "inbound": ["exit-vless-in"],  "outbound": "exit-out"  },
    { "inbound": ["exit-hy2-in"],    "outbound": "exit-out"  },
    { "inbound": ["exit2-vless-in"], "outbound": "exit2-out" },
    { "inbound": ["exit2-hy2-in"],   "outbound": "exit2-out" }
  ],
  "final": "direct"
}
```

`route.final = direct` 意味着**任何没有命中的流量都走直连**，中转只在被显式匹配的入口上生效。槽 1 的 tag 与字段名保持不变，存量客户端的节点名与订阅地址不受影响。

### 排错

| 症状 | 原因 | 处理 |
| :--- | :--- | :--- |
| 出口节点连不上，日志 `recvmmsg: connection refused` | 落地机 UDP 端口没放行，或地址/密码不对 | `nc -zvu landing.example.com 8443` 验证；重新 import |
| 自检 `✗ 出站连不通` | 落地侧 UDP 不通 / 密码错误 | 见上一行；**UDP 不通的落地不能当出口** |
| 自检 `⚠ 出站 IP 与落地机不一致` | 落地机自己也在中转 | 在落地机删除它自己的出口，或换一台 |
| 新增时报「端口已被占用」 | 入口端口被其它服务占用 | 换一个端口；`ss -tulnp \| grep :<端口>` 看占用者 |

### 延迟预期

中转必然叠加两段链路，延迟高于直连属正常：

* 上海 → 美西直连：约 100–160 ms
* 上海 → 美西（入口）→ 新加坡（落地）：约 300–350 ms

如果带标签的节点延迟和直连几乎一样，先确认客户端拉到的是新订阅（旧订阅可能还指着已删除的出口）。

<summary>❓ 常见问题解答 (FAQ)（点击展开）</summary>

#### Q1：没有域名可以使用吗？
完全可以。安装时在「域名」那一步输入 `ip`（直接回车会被拒绝，必须显式写 `ip`），即生成 10 年期 IP ECC 自签证书。客户端配置会自动注入 `skip-cert-verify: true`，网络连接质量、加密强度与正规域名证书完全一致。

#### Q2：为什么自签模式下订阅地址是 HTTP？安全吗？
这是为兼容主流客户端的必要设计：
1. 防导入阻断：主流客户端（Clash Verge、ClashX.Meta、Shadowrocket 等）拉取订阅时，底层 TLS 堆栈会严格阻断不受信任的自签证书导致无法导入；若用自签 HTTPS，用户必须手动将自签 CA 安装到系统受信任列表，极其繁琐。
2. 安全性保障：自签模式采用 HTTP 配合 24 位高强度随机 Token 路径隔离（例如 `http://<IP>:8444/<24位随机Token>/config.yaml`），全网扫描无法遍历订阅路径。建议在受信任网络下拉取；**要换成 HTTPS 只能重跑安装、在域名那一步填域名并签发证书**（证书模式装完即固定）。

> 订阅用 HTTP 还是 HTTPS 由 `CERT_MODE` 唯一派生：有真证书就是 HTTPS，自签就是 HTTP。没有可手改的字段——`SUB_PROTO` 早就删了，证书模式只能在安装期定。

#### Q3：机器上已有 Nginx 或其他 Web 站点，会有冲突吗？
互不影响，只需注意端口规划：
1. 80 端口零占用：Simple-Box 的 Caddy 专用于 8444 端口提供订阅地址，不监听 80 端口，80 端口完整留给既有 Web 服务。
2. 证书申请零冲突：域名证书仅走 Cloudflare DNS-01 API 验证，不走 HTTP-01，不需要占用 80 端口，与 Certbot 或 Web 服务器证书续签互不干扰。
3. 443 端口规划：
   - 若 443 端口已被 Nginx 占用，安装 Simple-Box 时将 Reality 端口设为其他端口（如 `20443`、`34443`）即可。
   - 若 Simple-Box 先占用了 443 端口，后续要把它让给别的服务，只能重跑安装向导、在协议集合里选「只装 Hysteria2」（或卸载）。

#### Q4：如果以后在同一台机器上用 Caddy 部署个人网站，卸载 Simple-Box 会受影响吗？
完全不会。Simple-Box 卸载时会自动扫描 `/etc/caddy/sites` 目录：
- 若检测到用户自建的其它站点配置，脚本会自动保留 Caddy 软件包、主 Caddyfile 及 `import sites/*.caddy` 引入行，仅安全移除本脚本的订阅配置并优雅重载，个人站点全程正常运行。
- 仅当 Caddy 是由本脚本全新安装且无任何外部站点时，才会彻底 purge 卸载软件包与配置。

#### Q5：域名证书申请失败，或者域名不在 Cloudflare 怎么办？
- 域名证书申请失败会**直接中止安装**（4.x 起不再降级自签）：降级的后果是「域名客户端全部 x509 失败，而日志说节点可用」。排查 CF Token 权限后重跑安装即可；确实要用 IP 直连，在域名那一步输入 `ip`。
- 域名证书仅支持 Cloudflare DNS-01 API。若域名在其他注册商，推荐直接使用 IP 自签模式，或将域名 NS 免费托管至 Cloudflare。

#### Q6：能用 IPv6 连接节点吗？
不能。Simple-Box 是纯 IPv4 脚本：节点与订阅都绑定 `0.0.0.0`，**完全不含 IPv6 代码**，也不读写任何 IPv6 相关的 sysctl 或 ip6tables 规则——装了这个脚本不会动你的 IPv6 配置。若 VPS 仅有 IPv6 地址，请勿使用。

#### Q7：为什么仅支持 Ubuntu 24.04+ 和 Debian 12+？
这两个主流发行版的官方系统仓库已内置 Caddy（v2.6.2+），无需引入任何第三方软件源、第三方 GPG Keyring 或编译环境，即可实现极简、稳定、无外部网络依赖的自闭环安装与运行。

#### Q8：开启出站中转后，原来的直连节点会受影响吗？
不会。中转是**额外的入口端口**（每个出口一组，默认 2053/2054、2083/2084），直连节点（443 / 8443）的 inbound、参数与订阅条目完全不变。删除出口后配置与订阅回到没有该出口时的状态。

#### Q9：为什么中转节点比直连慢？
中转要多走一段「入口机 → 落地机」，延迟天然叠加。中转的价值是**落地 IP**，不是延迟。如果只是日常浏览，用直连；需要干净落地 IP 时再切到 `-SG` 节点。
</details>

<details>
<summary>🌐 可选：让自有域名走直连（点击展开）</summary>

如果这台机器同时托管着你自己的服务（自建 DERP 中继、管理面板、订阅分发、SSH 等），这些流量应当直连而不是绕代理——DERP 尤其如此，走代理等于隧道套隧道，节点故障时 Tailscale 会一起失联。

在 `/etc/sing-box/env.conf` 里加一行，然后重新生成订阅即可：

```bash
DIRECT_SUFFIXES="example.com"          # 多个后缀用空格分隔
```

生成的 `config.yaml` 会在 `rules:` 段最前面插入对应的 `DOMAIN-SUFFIX,<后缀>,DIRECT`。留空（默认）则不插入任何规则。

模板与脚本本身不含任何私有域名，分享给别人时无需删改。
</details>
